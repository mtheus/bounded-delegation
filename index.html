Abstract

Coding agents now write most of the implementation in many teams, and a market of techniques has emerged to tell them what a system is and what it should do: specification kits, multi-agent methods, review plugins, skill collections, knowledge-base formats, and code-as-specification workflows. We conduct a multivocal review of eleven approaches (snapshot: November 2026), comparing them on nine criteria including directory structure, verification, drift control, and the three debts of Storey's model. No reviewed technique maintains an explicit architecture model across features; cognitive debt is a blind spot of the market; and verification splits into two disconnected worlds, one checking that prose is clear and one checking that behaviour is correct.

The Bounded Delegation Hypothesis: delegating implementation to coding agents is sustainable when, and only when, the delegation is bounded on both sides by artifacts humans own — Intent before the work (problem, domain language, decisions) and Evidence after it (inspectable executable scenarios and their results), with both bounds kept current by feedback.

Key findings

01

Intent is captured once, then forgotten

Almost every reviewed technique records the why at delivery; almost none keeps it current as the system evolves.

02

Cognitive debt is a market-wide blind spot

No technique measures whether the team still understands the system — only whether an artifact exists.

03

Verification splits into two worlds

Prose-based techniques check that specs are clear. Executable-test workflows check that behaviour is correct. None do both.

04

Agile rituals built for scarce hours lose their rationale

GitFlow, sprints, velocity, and line-by-line review existed to ration programmer hours. The scarce resource is now human attention.

05

A hypothesis, not a result

Six falsifiable sub-hypotheses (H1–H6), an evaluation agenda, and a full threats-to-validity section — nothing here is validated yet.

The seven knowledge layers

1Intent · HumanProblem — statement, target user, constraints, success criteria
2Intent · HumanDomain — ubiquitous business language, term by term
3Intent · HumanDecisions / ADRs — machine-checkable architectural assertions
4DelegatedStructure — C4 architecture model + co-located component contracts
5DelegatedPatterns — recurring implementation designs and workflow steps
6DelegatedSteps — active increments with delta specs over the layers above
7Evidence · HumanInspectable executable scenarios + automated evaluation suites
